# 数据库、GUI 与离线交付方案

本文件是[运行方案](02-technical-plan.md)的配套设计。数据库固定为官方 Windows x64 MySQL 5.7.44；GUI 在本项目内用 Win32/C++ 从零实现。官方文件导入和原始数据逻辑往返已有本机可复现实验；独立单文件引导首版已完成本机实测，GUI 和最终交付仍未完成。

## 1. MySQL 单文件发布

`mysql-standalone.exe` 是本项目独立编写的引导程序，内部封装官方 5.7.44 的最小完整 payload。解压后执行真实官方 `mysqld/mysql/mysqladmin/mysqldump`，而不是仿制数据库。源码、四个 PE、DLL、字符集、必要 share/plugin 文件和分发材料分别锁定来源与哈希。

当前版本为 15,906,304 字节，使用系统 Cabinet FDI 解压内嵌 LZX CAB，CNG 校验文件哈希，以 Win32 CreateProcessW 调用四个官方工具。`prepare INSTANCE` 解压到实例内 `.mysql/payload-<manifest hash>`；`mysqld|mysql|mysqladmin|mysqldump INSTANCE [官方参数]` 执行工具并转交标准输入输出与退出码，mysqld 的 basedir/datadir 固定在该实例内。并发准备使用文件锁，展开后校验再提交目录；已有缓存逐文件校验，失败明确返回错误，不覆盖数据库。

官方 5.7 客户端的 defaults loader 在本机不能读取中文绝对配置路径。子进程工作目录固定为实例目录，控制器使用 `--defaults-file=client.private.cnf` 这类固定相对文件名；该方式已在中文/空格/括号实例目录中完成 TLS 读写和备份还原。8.3 路径仍可能含中文，不能依赖它解决此问题。首版保留整个官方 share 目录，尚未做最终按访问记录裁剪。

复现命令为 `python tools/import_mysql_runtime.py`、`python tools/build_mysql_standalone.py`、`python tools/test_mysql_standalone.py`。首版测试只在开发机 Windows 10 完成，包含四工具版本、四进程并发准备、私有新库初始化、TLS、两行二进制数据备份/还原、已有库拒绝重新初始化、修改缓存拒绝运行与正常停服。VC++ 三个 DLL 的实际加载位置为实例缓存；Windows 10 的 UCRT 仍由系统提供，Win7 本地 UCRT 尚未实测。首版证据见 [单文件引导](evidence/p4-mysql-standalone.json)。

`initialize INSTANCE [PORT]` 已实现原生安全首次初始化：只接受没有 data 和数据库配置的新实例，使用官方 `--initialize`；经 `--skip-networking` 的随机命名管道，以官方临时密码设置 CNG 生成的 48 位十六进制密码，验证新凭据，再正常停库。写出的 `server.cnf` 固定本机地址、所选端口、lower_case_table_names=1 和 latin1；`client.private.cnf` 强制 TCP/TLS。data、配置与私有日志使用受保护 DACL，只允许当前 Windows 用户，data 的规则可继承到子文件。密码通过标准输入传 SQL，不进入命令行或普通输出。失败保留私有数据与诊断，不重新初始化既有实例。

安全版本在中文实例中实际完成初始化、重启、TLS、备份还原及正常关闭；预定 TCP 端口被独占时初始化仍成功，空密码 root 被认证拒绝，敏感目录/文件的实际 DACL 通过检查。已有实例重试不改变 data 中任何文件。证据见 [安全初始化](evidence/p4-mysql-secure-initialize.json)。GUI 密码设置、跨 Windows 用户迁移、备份/回滚控制流程仍待实现。

不得把“只携带四个 EXE”视为完整闭包。静态普通/延迟导入、运行期 DLL/插件/数据文件访问、中文路径、初始化、查询、备份、还原及 TLS 连接都参与闭包判定。VC++ 2019/UCRT 采用可分发且经 Win7/10/11 验证的本地部署组合，不能要求另装 VC Redist，也不能直接从开发机 System32 抄取 DLL。开发工具使用何种 CRT 不改变这一产品要求。

建议支持内部操作：查询版本、准备 payload、初始化空实例、启动/停止、mysql 客户端、备份与还原。具体命令行协议在实施阶段定义；GUI 和控制器使用受控操作接口，密码不出现在命令行或普通日志中。

首次运行流程：

1. 校验自身 payload 目录、清单和哈希，获取实例准备锁。
2. 解压到实例下的新临时目录；拒绝路径穿越、越界链接和重复路径，限制展开大小。
3. 校验全部展开文件和版本，成功后原子提交到按 payload 哈希命名的缓存；并发首启只产生一份有效缓存。
4. 仅对全新空数据目录执行 `mysqld --initialize`，在临时受控凭据流程中设置实例密码；初始化失败保留诊断，不触碰既有目录。
5. 启动前检查实例身份、数据目录、配置和端口占用；使用显式绝对路径与安全的 Windows 参数编码创建进程。默认绑定本机。
6. 验证 `SELECT VERSION()`、server UUID、目标库/表和基本读写，才报告数据库就绪；不以进程存在或端口可连代替。

已有数据目录禁止重新初始化。可写状态全部放在实例目录，不能写入只读安装目录；解压目录必须可由当前普通用户写入。没有管理员权限、Windows 服务注册、系统 PATH 修改、联网安装或隐藏自动升级。

## 2. 原始数据恢复与逻辑种子

资源调研已确认输入为物理数据库。恢复过程与新实例初始化严格分开：

- 从只读原包生成独立恢复工作副本，记录所有源文件哈希、MySQL 版本和恢复参数。
- 分析 `.frm`、MyISAM 配套文件、`ibdata1`、原配置与安装器自解压内容，核实引擎、字符集、排序规则、时区、SQL mode、触发器、事件、账号/权限和通道配置。本轮未执行安装器。
- 在同版本 Windows MySQL 下验证受控恢复。不能通过删除未知数据文件、覆盖原库或采用未验证的强制恢复级别宣称成功。
- 若能完整读取，导出可复现的应用逻辑种子及必要权限/配置；导入全新实例，核对结构、关键行、关联关系和服务实际查询。
- 未能恢复时保留失败证据，列出缺失的完整备份或逻辑种子。不得混入 `opendnf` 的现成数据、不同等级 PVF 或其他 MySQL 版本来冒充原包恢复。

`lower_case_table_names=1` 在初始化前确定，记录为 Windows/NTFS 偏差。先检查库、表、触发器及 SQL 标识符冲突，再迁移；不能只改文件名。源代码中使用的编码及旧认证行为需通过真实客户端/服务路径确定，不全局放宽 SQL mode、关闭校验或统一改成另一个字符集。

数据资源不进 Git；逻辑种子作为封样发布资产独立记录来源与哈希。未来由本项目编写的迁移代码可以版本化，真实玩家数据、密码、物理数据目录和用户备份始终排除。

## 3. 停服逻辑备份

“停服”指停止所有 DNF 写入进程并确认存档完成，MySQL 维持运行以便逻辑导出。默认流程是：锁定实例操作 → 检查磁盘空间 → 有序停服 → 确认写入者退出 → 一致性导出 → 校验归档 → 按操作前状态恢复运行。

原包存在 MyISAM，不能用 `--single-transaction` 单独证明所有表一致。选择经验证的全表锁导出或持有全局读锁的会话；锁必须覆盖实际导出周期，不能运行一条随后退出的 mysql 命令就认为锁仍有效。导出包括应用表、触发器、存储过程、事件及所需账号/权限元数据，具体选项依据引擎和字符集封样。

备份先写临时文件，检查子进程退出码、stderr、文件完整性和哈希，再原子命名。清单记录实例/版本、数据库集合、结构摘要、关键行数、时间、编码与校验信息；首次交付和后续抽样需在临时实例真实还原，不能把“文件非空”视为可恢复。

失败时保留旧实例和诊断，明确是否已恢复服务。只有服务再通过就绪检查后才显示恢复运行成功。凭据通过访问权限受控的临时配置或进程接口传递；不在命令行、备份明文元数据或日志中回显。

## 4. 预快照、还原与回滚

推荐使用数据目录代次和活动指针，避免原地破坏现有数据：

```text
instances/<id>/db/
  active.json                 当前代次及版本身份
  generations/<generation>/   各自完整 datadir
  snapshots/<operation>/      停库后的预快照及清单
  operations/<operation>.json  可恢复的操作日志
```

还原状态机：

1. **检查**：验证备份格式/版本/哈希、实例 UUID、目标路径、所需空间和当前服务状态；禁止并发启动、备份或切换等级。
2. **停服与预备份**：正常停止 DNF，保持 MySQL 运行生成并校验当前逻辑备份；失败则不继续破坏性步骤。
3. **冷快照**：正常停止 MySQL，确认进程和数据句柄释放，复制完整旧代次到预快照并核对清单。磁盘不足或快照失败则中止。
4. **影子还原**：在新代次初始化同版本 MySQL，用隔离本机端口导入备份；不覆盖旧代次。检查版本、表结构、行数/关键查询、触发器、权限与必要配置。
5. **切换**：停止影子库，持久化操作日志，原子替换 `active.json`，再按目标配置启动新库和服务。切换使用普通文件原子替换，不依赖需要提权的符号链接。
6. **业务确认**：DB 与受影响服务通过就绪/存档读取检查后提交操作。保留预快照与操作记录。
7. **失败回滚**：停止新代次，切回未被导入修改的旧代次，校验并重新启动；若旧代次有损坏才从冷快照恢复到另一代次。回滚失败时保持停服并报告可用快照，不报告成功。

原子指针切换不等于整个流程天然原子。对磁盘写满、SQL 导入错误、mysqld 崩溃、GUI/控制器被终止和每个切换窗口做故障注入。控制器重启后依据持久操作日志和进程真实身份恢复到明确状态，不能盲目继续导入或自动删除旧代次。

恢复时每一条 destructive 操作都限制在已验证的实例根目录内。端口或 PID 相同不足以证明进程归属，需要进程启动身份、配置、server UUID 与 datadir 一起核对；不得停止或写入用户已有 MySQL。

## 5. 自研 Win32 GUI

GUI 使用 Win32 控件与 C++ 消息循环，调用实例控制器，不加载参考 `Launcher.cs`、参考 EXE 或历史 GUI。耗时操作在工作线程/子进程执行，以操作 ID 和异步事件更新界面；窗口不能因备份或停服阻塞。

| 界面能力 | 具体行为 |
|---|---|
| 服务列表 | 展示 19 个服务及 MySQL；区分 core/full、未安装、停用、加载、监听、业务就绪和失败，不伪造缺失组件状态 |
| 启动 / 停止 | 单项和整实例操作，显示依赖、当前步骤、失败位置和正常/强制退出结果 |
| 日志 | 按实例、服务、等级、时间过滤；支持中文路径、滚动与导出脱敏诊断 |
| DB 设置 | 连接参数、密码、端口、实例身份与验证结果；配置校验通过后再保存应用 |
| 备份 / 还原 | 选择目标、显示预快照、进度、校验、切换及回滚状态；失败保留恢复入口 |
| 插件 / Frida | 明确当前配置与兼容状态，开关在受控重启后生效，不承诺危险的任意热卸载 |
| 等级配置 | 选择匹配 ELF/PVF 配置，停服后切换并核验哈希；宿主构建保持一致 |

GUI 首启只要求选择已有本地实例配置或准备封样资源，不展示开发工具链、TLS 重写等实现细节。未准备组件给出可操作的实际状态，不能在产品界面使用“通过了多少函数”作为运行进度。

密码保存在用户权限范围的本地配置或受控凭据存储，敏感配置不进 Git。若采用绑定 Windows 用户/机器的保护方案，必须明确其导出、跨机器迁移与恢复行为，不能破坏解压迁移能力。

## 6. 离线包与依赖白名单

候选发布形态：

```text
DNF-Native/
  DNF-Native.exe              自研 Win32 GUI
  instance.json               本项目统一实例配置
  suite/
    host32.exe / host64.exe   自研宿主
    mysql-standalone.exe      自研引导 + 官方 payload
    linux/i686/、x86_64/      固定用户库闭包
    assets/                  原始 ELF、插件、单份 PVF 和所需数据种子
    licenses/、manifest.json  来源、许可证和逐文件身份
```

这是逻辑组织，不能为了表面文件少省略实际依赖。各服务需要的路径由本项目独立生成配置并建立实例映射；参考工程配置不得进入包。用户资源与可写实例状态分离，不在首次运行时下载资源。

| 包 | 目标内容 | 成立条件 |
|---|---|---|
| core | 16 个可玩原版服务、DP2/Frida、MySQL 单文件、自研 GUI/宿主、完整必需库及单份 PVF | 业务证明安全三件套和列为可选的组件可移除，ZIP 实测达标 |
| full addon | 安全三件套、必要 TSS/antisvr、70S2 配置及差异资产 | 源文件封样、依赖闭包和完整 19 服务验收；不重复默认 PVF |

70S2 的具体资源、ELF/PVF 匹配和差异包尚未找到并封样；不能宣称已经可用。如果另一等级确需不同 PVF，作为显式版本资源单独处理，不能把不匹配文件与默认 PVF 拼成“无重复”结果。

正式门禁直接测最终 ZIP 字节数，暂以更严格的 **210,000,000 字节**解释 210 MB。默认 core 的目标保留；full addon 约 40 MB 是预算。需求“最终 ZIP”是否还包括合并 full 包需审阅明确，在此之前不把任何合并超限包描述为达标，也不默认放宽上限。

依赖裁剪按“候选 → 静态闭包 → 代表性路径访问记录 → 删除候选 → 全场景复验”执行。压缩格式和去重措施不得改变原始 ELF、机器码地址或 PVF 内容；补丁写派生内存/缓存。不能用额外在线下载、用户另装 MySQL、删除必需插件或拆出必需资源规避离线/体积要求。

发布清单记录每个文件的原始来源、SHA-256、角色、许可证、默认/可选归属和自研构建提交。自研 PE 应能追溯到本项目源码；第三方库来自锁定官方/发行版来源，原版资产来自封样原包，均不从参考构建目录取货。发布审计采用文件与构建来源白名单，不能只按文件名黑名单检查。

## 7. 三系统与普通用户离线验证

最终在独立 Windows 7/10/11 x64 实机或原生安装环境执行，环境不包含开发工具、Python、VC Redist 的预装便利依赖或其他项目目录。断网、普通用户、中文/空格/括号目录、不同磁盘路径、端口占用、资源不足和重启均覆盖。Win7 SP/补丁与 CPU 基线单独列明；本轮没有执行这些测试。

所有验收从同一个发布 ZIP 解压开始，核对清单，记录系统构建、输入哈希、自研提交、配置、日志、协议和数据结果。参考源码重编服务、参考 GUI、历史 MySQL SFX 或历史宿主的输出不进入这条证据链。
