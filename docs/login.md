# 独立简单登录器

`resources/DNFLogin.exe` 放到客户端 `dnf.exe` 旁使用。它由用户提供的 C 登录器整合而来，源码位于仓库 `src/login/`，正式运行目录不附带源码。不依赖 DNF Native 控制台，不读取服务实例，不要求客户端访问服务端目录。

## 使用与密钥

默认连接和游戏账号由用户明确指定公开，登录器直接填写并显示，无需隐藏或手动改名：

| 项目 | 默认值 |
| --- | --- |
| 数据库地址／端口 | `127.0.0.1`／`3306` |
| 数据库账号／密码 | `game`／`uu5!^%jg` |
| 游戏账号／密码 | `test`／`123456` |

新建实例自动准备上述连接和完整四表的 test 账号。把 `resources/DNFLogin.exe` 复制到客户端 `dnf.exe` 旁后，默认本机服务可直接登录；使用远程地址或自定义账号时仍手动修改。登录器保持独立，不读取服务实例配置。数据库远程连接仍由管理员配置监听和网络访问。维护连接使用自己的私有密码，不填入登录器。

旧实例不会因打开新版而自动修改玩家账号或数据库密码。其实际登录配置在实例 `login.private.cnf`，控制台数据库“详情”直接显示连接参数；按需在备份后同步为默认值。错误密码现在明确显示“数据库认证失败”，并保留 MySQL 的原始原因。
“导出密钥对”选择目录后生成当前生效的两个 PEM：

| 文件 | 用途 |
| --- | --- |
| `private_key.pem` | 放在客户端的 `DNFLogin.exe` 旁，用于签发登录令牌 |
| `publickey.pem` | 放在服务端实例 `home/neople/game/`，用于原版 game 验签 |

`private_key.pem` 由登录器读取，`dnf.exe` 接收签名令牌、不读取这份私钥。登录器无外部私钥时使用内置默认私钥；本项目新实例默认公钥已经与其配对，无需再手动替换。该默认配对按用户授权公开纳入仓库，不是私人凭据。已有实例保留自己的公钥；若需改用本登录器，先正常停服、备份原公钥，再替换为导出的公钥并重启 game。

登录器旁的有效 PKCS#1 `RSA PRIVATE KEY` 优先于内置密钥，导出按钮同时导出它对应的真实公钥；外部文件无效时明确拒绝启动，不回退到其他密钥。导出不覆盖已有同名文件。若要使用自有密钥，客户端私钥和服务端公钥必须一起更换。

启动游戏始终以登录器所在目录为工作目录，支持包含中文及空格的路径。已有 `GAME_SERVER_IP` 环境变量继续优先；未设置时以填写的数据库地址作为单机套件默认游戏地址。数据库与游戏分机时由客户端启动环境显式设置 `GAME_SERVER_IP`。登录器不改写客户端文件或全局系统环境。

当前仍沿用原登录器的 MySQL 原生密码认证、四表注册及旧令牌格式。注册附属表写入失败会明确报错，需要管理员检查四张表，不宣称注册成功；跨表原子恢复尚未实现。完整客户端、城镇和战斗的验证边界见 `validation.md`。

默认配对已内置：正常使用只复制登录器，不必导出 PEM。导出按钮直接生成两端所需的准确文件名，用户无需改名。

## 构建

在完整仓库中运行：

```powershell
python -B tools/build_login.py
```

使用项目固定的 LLVM-MinGW 20261104 MSVCRT，输出在 `../x/dnf-native-output/login/`。默认私钥仅存于 `resources/login/private_key.pem`，构建在外部生成内嵌头文件；构建同时验证原登录令牌向量和默认公钥配对。`build_all.py` 自动构建并打包登录器。

正式目录按 `AGENTS.md` 只包含运行文件。源码、默认配对、测试及构建脚本随项目仓库管理；构建收据及验证现场留在 `../x/`。
