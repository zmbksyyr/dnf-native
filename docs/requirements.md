# DNF 台服服务端 Windows 原生运行 · 需求整理

> 本文只整理需求、约束与验收标准；不包含实现进度结论。

## 1. 项目目标

在 **Windows 7/10/11 x64** 上，原生运行**原版 DNF 台服服务端 19 个 Linux 进程**：

- 16 个 `df_*` 服务：
  - `stun`
  - `monitor`
  - `manager`
  - `relay`
  - `bridge`
  - `channel`
  - `dbmw_guild`
  - `dbmw_mnt`
  - `dbmw_stat`
  - `auction`
  - `point`
  - `guild`
  - `statics`
  - `coserver`
  - `community`
  - `game`
- 3 个 secsvr 进程（如果不是必需，就移除）：
  - `gunnersvr`
  - `secagent`
  - `zergsvr`

全部进程必须是**原版 Linux ELF 二进制**，由本项目自己的 runtime/loader 加载运行。

## 2. 运行环境与限制

- 目标系统：Windows 7/10/11 x64。
- 不依赖：
  - 虚拟机（VM）
  - WSL
  - Docker
  - 内核驱动
  - 模拟器
- 不要求安装 Linux 系统或额外运行环境。
- 交付物解压即用，离线可运行。
- 不要求管理员权限，不安装 Windows 服务。

## 3. 参考实现使用红线（最高优先级）

允许把 `dnf-winport` / `rednf` 作为**只读参考实现**，用于理解 ABI、行为和设计，但：

1. **不得用参考工程的源码编译产物交付**
   - 参考工程的 `win-port/elfload`、`compat`、服务源码、脚本等，编译出的 exe/dll/so/加载器，不得进入交付包、验收链或启动链。
2. **不得使用参考工程的 GUI 交付**
   - 不得复制、修改后使用、重新编译或直接发布其 `Launcher.cs`、`服务端控制台.exe` 等。
   - 最终 GUI 必须在本项目内从零实现，原生 Win32/C++ 优先。
3. **19 个进程必须是原版 ELF**
   - 包括 x64 的 `df_stun_r` 和三个 secsvr 进程。
   - 不得用 rednf 源码重建的服务、加载器或“重编版”冒充原版。
4. **参考代码必须 clean-room**
   - 任何参考工程的代码、字节表、补丁或生成器进入本项目前，必须在本项目内重写并记录来源/差异。
5. **参考产物不得进入交付**
   - 不得把参考源码的编译产物、配置文件或 GUI 放进 ZIP/绿色包。
   - 参考工程只能在隔离实验中运行，结果必须标注“参考，不是交付”。

## 4. 必须保留的能力

1. **原版进程与地址**
   - 原版 `df_game_r` 的地址、入口、机器码布局不被随意改变。
   - 按原地址编写的机器码补丁仍然可用。
2. **DP2 / Lua**
   - DP2 插件链、Lua 初始化、脚本加载保持可用。
3. **Frida**
   - Frida 脚本可加载、可 hook、可双向调用。
   - 保留原版函数导出/地址语义。
4. **等级文件**
   - 可直接替换不同等级的 `df_game_r` / `Script.pvf`，不需要重新编译加载器。
5. **机器码补丁**
   - 保留按原版地址/机器码打补丁的能力。

## 5. MySQL 与数据库

- 数据库版本：**MySQL 5.7.44**（Windows x64）。
- 发布形态：**单个 `mysql-standalone.exe`**
  - 自解压官方 5.7.44 最小 payload；
  - 包含 `mysqld`、`mysql`、`mysqladmin`、`mysqldump`；
  - 不安装 MySQL 服务；
  - 不要求单独安装 MySQL。
- 数据目录：
  - 使用实例自己的数据目录；
  - 不覆盖原包数据库；
  - `lower_case_table_names=1` 是已记录的 NTFS 偏差。
- GUI 必须提供：
  - 数据库备份；
  - 数据库还原；
  - 默认停服逻辑备份；
  - 还原前预快照；
  - 失败回滚。

## 6. GUI 要求

- 最终交付**原生 Win32 GUI**。
- GUI 必须由本项目自研，不得使用参考工程 GUI。
- 至少包含：
  - 19 个服务/MySQL 的启动、停止、状态查看；
  - 日志查看；
  - 数据库备份/还原；
  - 数据库连接/密码配置；
  - Frida/插件开关；
  - 解压即用、离线运行。
- GUI 不得依赖参考 `Launcher.cs` 或 `服务端控制台.exe`。

## 7. 交付物与体积

- 离线 ZIP 包，解压即用。
- **ZIP 目标 ≤210 MB**。
- 默认 core 包：
  - 16 个可玩服务；
  - DP2/Frida；
  - MySQL 单文件；
  - GUI。
- 可选 full addon（约 40 MB）：
  - 安全三件套（仅保留核心游戏服务端组件，无关的移除）；
  - TSS/antisvr（仅保留核心游戏服务端组件，无关的移除）；
  - 70S2。
- 不重复携带 `Script.pvf`。
- 不把可选组件塞进默认包。
- 包内不得包含参考工程源码编译产物或参考 GUI。

## 8. 验收标准

1. **原版进程**
   - 19 个原版 Linux ELF 进程能启动；
   - 能监听对应端口；
   - 能互相通信；
   - 能读数据库；
   - 能写日志。
3. **DP2 / Lua / Frida**
   - DP2 初始化成功；
   - Lua 脚本正常；
   - Frida 脚本双向调用正常。
4. **数据库**
   - MySQL 单文件首次运行可初始化；
   - GUI 备份/还原可复现；
   - 失败可回滚。
5. **离线与体积**
   - 干净 Windows 解压即用；
   - 断网可运行；
   - 最终 ZIP ≤210 MB。

## 9. 明确不接受的替代方案

- 用 rednf 源码重建服务代替原版 19 进程。
- 用参考加载器编译产物代替本项目 loader。
- 用参考 GUI 代替自研 GUI。
- 用 VM/WSL/Docker/模拟器/驱动绕过原生运行。
- 用“进程存活/端口在听”单独冒充“服务就绪”。
- 用源码重建或参考 GUI 的运行结果计入最终验收。
