# 客户端认证与原数据库兼容

私有客户端关闭 `simplified_pvf` 后，原包 PVF 对照中的频道名称恢复可读。本轮双方使用相同的原包 PVF；当前 jbz69 定制 PVF 的缺失动画模板问题仍单独保留，不能混为一项通过。

## 连接与密钥

原版 `AcceptThread` 在来源 IP 等于 `system_monitoring_ip` 时直接关闭连接，默认回环地址误伤同机客户端。原版访问器 `0x0857f436`、比较 `0x0857cfe0` 和关闭分支 `0x0857cff4` 已核对；配置设为 `0.0.0.0` 后已读取确认实际运行值。新建实例生成配置时加入该值，不修改原版 ELF。

验证使用独立生成的临时 RSA 密钥对，私钥只在忽略目录。重建公钥 SPKI 与实例公钥逐字节一致。实际客户端进入原版 game 后记录 `[Taiwan, Auth] Success!!`，UID、账号、时间戳均解析成功，证明本轮使用的密钥匹配，不表示任意外部登录器都已配置正确。

后续选角断线来自测试账号数据：`member_info.user_id` 应为票据中的数字 UID；`taiwan_login.member_login` 缺少测试 UID；可选身份资料填入了无效密文。逐项备份并仅修正自建测试身份后，原版记录 `Success Token reuse login.`，角色列表不再显示断线提示，且可打开建角界面。认证和资料校验保持原样。

## 数据库生成遗漏

原包 `originals/database-source/etc/my.cnf` 设置 `sql_mode = NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION`，本项目初始化遗漏该配置，使用 MySQL 5.7 默认严格模式。真实数据库错误包括零日期拒绝和数值越界；原版建角 INSERT 省略的 `last_play_time` 默认值为零日期。单文件初始化现恢复原包模式，开发准备脚本同步处理。

原种子的 11 个存储过程使用 `game@%` 定义者。未导入原系统账号时，该定义者不存在，实际产生 MySQL 1449。新建实例现生成随机密码且锁定的 `game@%`，仅授予过程所在 `taiwan_cain`、`taiwan_billing` 两库权限；原过程定义保持原样，不开放该账号登录，不授予全局权限。

真实日志另发现当前月 `taiwan_cain_log.log_response_time_YYYYMM` 缺失。创建实例时按原种子 `log_response_time_202004` 结构建立，与既有拍卖月表采用相同方式。原应用库种子往返仍逐字节一致，月表及实例账号在核对后生成。

## 实测与边界

最终单文件通过初始化、权限/TLS、真实零日期及越界 INSERT、备份恢复和正常停库。最终 GUI 首次创建专项通过两份实例、18 库 606 表、原种子往返、锁定定义者执行原存储过程、15 个原版 peer 协议和 Frida 数据库接口，全部服务正常退出。

该阶段数据库修正后重试客户端，连续在登录前显示“图表系统建立失败”，当时最后一次退出为 `0xc0000005`。临时网络诊断 DLL 已从私有客户端移除；原客户端及原版 ELF 哈希未变。随后已实际完成建角、洛兰通关、结算、回城及冷重启后的存档读回，客户端正常退出 0；实测配置、客户端插件边界、停服超时及后续性能修复见[真实游戏与缓存记录](13-gameplay-and-cache-performance.md)。图形初始化错误仍会复现。

本阶段审阅程序位于 `build/review/DNF-Native.exe`，当时 ZIP 为 190330912 字节；该目录现已由[后续 GUI 阶段](12-gui-reference.md)更新。此阶段源码、构建、回归、认证标记和截图哈希见[阶段证据](evidence/p10-client-auth-and-database.json)。验证仅限本机 Windows 10；本阶段完整备份回滚和原生日志专项沿用先前版本结果，未重复计为本轮通过。
