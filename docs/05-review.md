## 1. 需要审阅的具体决策

| 事项 | 方案建议 | 尚未消除的限制 |
|---|---|---|
| 运行路线 | 原版 Linux 用户库 + 自研 Linux 内核 ABI 兼容层；先通过 P1 六类关卡 | 本轮静态分析不能证明可运行，不沿用历史工程结论 |
| 原址与局部适配 | 原文件和主程序地址保留，必要 TLS/syscall 仅作可追溯的原位窄改写 | 需要确认此边界符合机器码保留要求；与原有补丁/hook 的共存必须实测，失败不降标 |
| Win7 最低环境 | 建议以明确的 Win7 SP1 x64、补丁与 CPU 组合封样，依赖全部随包本地部署 | 用户原文只写 Win7，未经审阅不将 RTM/补丁需求静默排除；VC/UCRT 和 Frida 仍待核实 |
| 19 与默认 16 | 完整模式继续验收 19；只有真实业务对照证明不必需后才允许 core 移除三件套/可选库 | 原始默认启动链包含三件套；TSS/antisvr 等依赖不能靠改名或桩替代 |
| ZIP 口径 | 以 210,000,000 字节为严格门禁，core 达标；addon 独立预算约 40 MB且不重复 PVF | “最终 ZIP”是否含合并 full 包待确认；保留全部候选资源时 raw DEFLATE 已约 207.6 MB，预算尚未闭合 |
| 数据与等级封样 | 优先恢复原物理库并形成逻辑种子，封样匹配客户端、第二等级与 70S2 差异资源 | 数据库恢复未试验；第二等级/70S2 与匹配客户端尚未验证，不能直接混用其他包 |

以上是具体设计决策与验收边界，用户审阅前只保留为建议，不启动 P1。普通实现细节在确认的路线内自行处理，不因日常可逆操作反复请求许可。

## 2. 本轮已确认的事实与未确认项

已从原始 `DOF.tar.gz` 重新清点 51 个 ELF、19 个启动项，保存原文件哈希、架构、入口、动态依赖、版本和 TLS 信息。`MySQL.tar.gz` 确为物理数据；四个 Windows MySQL 程序有 VC/UCRT 依赖。完整静态证据与可复核的审计脚本已提交。

尚未确认：原版执行、完整动态依赖与 syscall/TLS 路径、Win7 后端、DP2 保护库、Frida/补丁共存、三件套可选性、数据库恢复、两等级切换、70S2 资源、实际可玩链、最终体积和三系统离线运行。网络文档、静态解析和历史项目结果均不能填补这些空项。
