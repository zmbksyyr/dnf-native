# GUI 与原版日志查看

此前窗口将数据库操作、插件开关、服务列表和操作摘要纵向堆叠，真正的应用日志没有独立查看区域；点击日志按钮只会一次性将 stdout/stderr 混入控制台记录。本轮针对这两个实际问题调整本项目原生 Win32 GUI，没有引入界面框架或参考 GUI。

左侧显示服务及其进程状态、PID 和单独启停操作；右侧提供较大的日志阅读区域；数据库启停、备份还原与实例操作集中到底部。整体启停位于顶部，插件设置保留在服务区域。列表的运行状态只表示进程状态，业务验收仍以原版应用和实际请求为准。默认窗口 1180×820，最小 1040×760，字体与布局按系统 DPI 缩放；尚未在独立高 DPI 系统验收。

日志来源可以切换：

- **应用日志**：直接读取所选服务工作目录下 `log/` 中的文件，包括 game 的 `.init/.cri/.error`、channel/bridge 的 Info/Error 日志等。默认优先初始化或进程信息文件，停服后仍可查看；再次打开 GUI 也能发现已有日志。
- **标准输出**：原版服务的 stdout 文件。
- **标准错误 / 宿主诊断**：原版 stderr 与宿主的真实诊断共用既有文件，明确显示来源。
- **MySQL 原生日志**：本实例最新的实际服务器日志。
- **控制台操作**：GUI 自己的操作记录，单独显示，不附加到原版日志内容中。

日志保留原文，只将换行转为 Windows 文本框需要的 CRLF。默认尝试 UTF-8，再按系统代码页解码；也可明确选择 UTF-8、简体中文 936、繁体中文 950 或韩文 949。GUI 不修改应用日志编码、刷新策略或缓冲方式；应用尚未刷出的内容要等应用写入文件后才会出现。

自动检查文件变化，读取末尾至多 256 KiB，较大文件在路径栏提示截取范围；不会反复载入完整历史文件。支持追加、截短、轮转后同路径重建以及手动刷新；取消跟随滚动时保留阅读位置和选择，开启时定位到最新内容。日志目录按钮打开当前来源所在目录。原文件没有裁剪、改写或删除，完整内容仍在实例目录。

专项使用独立实例，先以明确标记的夹具检查编码、追加、轮转、截取和滚动，再启动实际原版 game 与 15 个 peer。实际检查应用 `.init`、stdout、stderr、MySQL 文件与正常停服后的退出日志，同时复核 channel、relay/monitor 和 STUN 请求。常规与最小窗口均保留截图；原始日志和含本机路径的截图保存在忽略的 `build/probes/`。结果见[本轮证据](evidence/p8-gui-original-logs.json)，不计 jbz69 客户端业务、完整安全拓扑或干净 Win7/11 验收。

开发复现（目标必须是已停止的独立测试实例）：

```powershell
python tools/build_mysql_standalone.py
python tools/build_gui.py --build-dir build/gui-logs
python tools/test_gui_logs.py --instance PRIVATE_INSTANCE --gui build/gui-logs/DNF-Native.exe
```

审阅程序仍使用 `build/review/DNF-Native.exe`；ZIP 同名更新，资源 CAB 和原版 ELF 内容保持对应上一阶段的校验结果。当前包的成员哈希与 CRC 检查记录在本轮证据中。
